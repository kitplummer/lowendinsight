# The corpus the cache baseline is measured against.
#
# Fifty public repositories, chosen to be what a customer actually scans: an
# application with a real, resolved dependency set, not a library with four
# dependencies of its own. GitHub's dependency-graph SBOM gives the transitive
# closure, which is where misses cluster -- the caller has never heard of those
# packages and neither have we.
#
# Ecosystem mix is deliberate and includes ecosystems we cannot resolve yet
# (Go, Ruby, Java, .NET). Those come back as {:unsupported_ecosystem, _} and
# quantify a gap that would otherwise be invisible: a customer scanning a Go
# service gets nothing from us today, and the baseline should say so in numbers
# rather than leave it to be discovered.
#
# Every repository here was checked on 2026-09-28 to have a dependency-graph
# SBOM GitHub will actually export. Seven candidates were dropped for reasons
# worth knowing before anyone adds to the list:
#
#   * a library does not commit a lockfile, so its graph holds four or five
#     packages -- its CI actions -- and none of its ecosystem. ecto, oban,
#     broadway and axon all looked like Elixir coverage and measured nothing.
#     Applications only.
#   * GitHub times out generating the SBOM for the largest repositories
#     (vercel/next.js, grafana/grafana return 500). Nothing on our side can fix
#     that.
#   * an archived repository's graph goes stale or 404s (localstack).
#   * our own repository returns 404 for its SBOM, which is worth chasing
#     separately: the dependency graph appears not to be exporting for it.
#
# Keep this list stable. Changing it changes the number, and the point of the
# measurement is to repeat it after a preload and see whether the money moved it.
